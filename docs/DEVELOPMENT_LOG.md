# Development Log

## 2026-11-08 — Phase 1 + Phase 2 (+ core of Phase 4)
Built: monorepo, PostgreSQL schema (append-only audit/response/assessment tables), Express API (auth, RBAC, hospital isolation, newborns, observations, device gateway endpoints, devices, alert lifecycle, response log, audit, WebSocket events), intelligence package (plausibility-based data-quality checks, trend slope, configurable illustrative rules).
Tests executed: 27 passing (7 unit, 20 API integration) against local PostgreSQL 16.
Problem found by tests: stored device state "disconnected" made ingestion mark all readings unavailable. Fixed: a message from a device is evidence of connection; lateness is handled by the delayed-message check.
Not yet built: simulator, device-gateway service, React frontend, Azure AI abstraction, Docker files, e2e tests, remaining docs.
All data synthetic; all thresholds illustrative and not clinically approved.

## 2026-11-08 (later) — Phase 3: simulator and device gateway
Built: device-gateway service (simulator adapter -> standard observation format -> validation -> forwarder with in-memory buffering and ordered resync), synthetic simulator with scenarios A-F (all labelled synthetic), API endpoint for gateway hospital discovery.
Tests executed: 39 passing (8 unit, 20 API integration, 11 pipeline/gateway). Live smoke test with real API, gateway and simulator processes: scenario B stored 64 observations and raised 1 high-priority illustrative alert.
Defect found by tests and fixed: the "unreliable data" rule examined the last 3 readings across all sensors, so healthy sensors masked a failing one. It is now evaluated per measurement type (regression test added).
Known limitations: gateway buffer is in-memory (lost on restart); the simulator is the only adapter; no physical device has been connected.

## 2026-11-08 (later) — Phase 5/6: React clinical workspace
Built: Vite + React + TypeScript app (login, layout with sidebar, mobile nav, breadcrumbs, search and notifications; Overview; Newborns with registration; Newborn profile with 5 tabs; Live Monitoring; Clinical Alerts list and detail with acknowledge, assess, escalate and resolve dialogs; Response Log; Devices with register, assign and unassign; Settings). All screens use real API data; realtime updates via WebSocket with polling fallback. API additions: hospital, units, users, roles, alert rules (read-only), change-password.
Tests executed: 39 API, pipeline and unit tests passing; 20/20 browser checks (tests/e2e/ui_workflow.py, Playwright + Chromium) covering login redirects, monitoring staleness labels, the alert lifecycle through the UI, role restrictions, duplicate handling and mobile layout.
Defects found and fixed: clipped acknowledgement chip on monitoring strips; repeated chart time labels; E2E data pollution because `npm run seed -- --reset` was swallowed by npm (added `npm run seed:reset`).
Known limitations: production bundle over 500 kB (no code splitting); hospital and unit context is informational only; alert rules are read-only; no accessibility audit with assistive technology; browser tests run on Chromium only; the sandbox does not keep servers running between commands, so demos must be started together.

## 2026-11-09 — Phase 7: AI assistance (Demo Mode)
Built: provider interface with a local template provider (labelled "Demo Mode – Not Connected to Azure") and an Azure OpenAI provider written to the documented REST contract but NEVER executed against Azure (no credentials). Four read-only tools (alert, recent observations, response history, guidance), each gated by the requesting user's own permission and hospital. Fixed controlled workflow (the model does not choose tools). Anonymised bundle (no newborn or user identifiers). Output safety filter on every provider's output (diagnosis, treatment, dismissal/resolution, reassurance, autonomous-decision language). Drafts contain three clinician-only placeholders; the assessment endpoint rejects any draft still containing them. Append-only ai_interactions table plus audit entries for every request, tool call and denial. Permissions ai:summarise (Doctor, Nurse) and ai:draft (Doctor). Oversight tab in Settings. Local knowledge base contains system documentation only; NO clinical guidance is loaded.
Tests executed: 72 automated tests passing (adds 33 AI tests including stubbed-network Azure paths: unsafe output withheld, unavailable Azure falls back to demo, placeholders re-added); 15/15 AI browser checks; earlier 20/20 workflow browser checks.
Defect found and fixed: response events written in one transaction shared a timestamp and were ordered by random UUID, so the order of "assessment recorded" and "response documented" was nondeterministic. Added a sequence column (migration 003) and ordered by it; verified over 6 repeated runs.
Known limitations: the demo provider is templated text, not a language model, so hallucination and prompt-injection behaviour of a real model are NOT evaluated; the Azure provider is untested against real Azure; no Azure AI Search retrieval; knowledge base is not clinical guidance; bias and consistency evaluation not performed beyond deterministic checks.

## 2026-11-12 — Real generative AI integration (Azure OpenAI)
Built: Azure provider using the official `openai` package's `AzureOpenAI` client (API version 2024-10-21 per Microsoft's current JavaScript guidance; API-key auth, plus optional keyless Entra ID, untested); anonymised minimum-necessary payload with stable record ids and relative times; privacy guard against real identifiers; strict output validation (schema, headings, source references, number grounding, measurement grounding, base and strict safety patterns); server-written clinician-only draft fields; explicit mode choice with no silent fallback; categorised failure handling (credentials, misconfiguration, rate limit, timeout, outage, content filter, malformed, rejected output); in-flight duplicate guard; migration 004 (model, role, validation, latency, error category, request digest; kinds; ai_draft_decisions); accept/reject decisions; administrator connection test and `npm run ai:check`; new request types (trend explanation within summary, documentation checklist); interface changes (source selector, distinct real-vs-template styling, source chips, missing-information list, checks panel, reject, error with explicit Demo Mode switch, admin oversight).
Tests executed: 141 automated (adds 33 unit + 40 integration for Azure, against a LOCAL MOCK via the real SDK); 53 browser checks (20 + 15 + 18). 
Defects found: SDK timeout error shape misclassified (found by the real-SDK integration test); validator initially missing the base filter; seed reset dropped alert rules.
NOT DONE: no real Azure connection was made. Real-model accuracy, hallucination, bias, consistency and injection behaviour are unevaluated. Keyless auth untested.
