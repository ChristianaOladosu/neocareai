# Demonstration Script (about 9 minutes)

Goal: show one connected story, from a measurement to an accountable clinical response, with **controlled AI assistance** as the visible differentiator. Everything shown is synthetic. Say so at the start.

## Decide the AI segment before you start (this controls what you may say)

| If this is true on the day | Run the AI segment as | You may say |
|---|---|---|
| Azure is not configured, or `npm run ai:check` has **not** passed on your deployment | **Demo Mode** (default; no setup) | "This is Demo Mode: fixed templates, no AI model, not connected to Azure. We have implemented the real Azure OpenAI integration and tested it against a simulated Azure service; it is ready to be connected." |
| `npm run ai:check` passed **today** on your own Azure deployment and Settings → AI assistance shows "Last test: connected" | **Azure OpenAI** (choose it in the selector) | "This summary was generated by a real model on Azure OpenAI from anonymised data, then checked by our validators. Checks passing does not mean it is clinically correct." |

**Never** say "powered by Azure" or "uses GPT" unless the second row is true. If Azure fails live, do not apologise or hide it: show the error, click **Switch to Demo Mode and run again**, and say so. That is the designed behaviour.

## Setup (10 minutes before)

```bash
npm run seed:reset
npm run api         # terminal 1
npm run gateway     # terminal 2
npm run web         # terminal 3  -> http://localhost:5173
```

Open three browser windows (or profiles), each signed in: **Doctor** (`doctor@demo.neocareai.test`), **Nurse** (`nurse@…`), **Administrator** (`admin@…`), password `DemoPass#2026`. Put the Doctor window on **Live Monitoring**. Keep `bash scripts/demo-scenarios.sh` ready in a fourth terminal. Do not start it yet. Test once, then `npm run seed:reset` again.

## If something goes wrong

- Alert slow to appear: measured at ~52 s after the scripts start (whole run about 92 s); keep talking about quality and disconnection. If still absent, run `npm run simulate -- --scenario=B --device=SIM-MON-01 --fast` (instant, same alert).
- Readings all show "Not current": scenarios ended more than 2 minutes ago. This is the feature working. Run `npm run simulate -- --scenario=A --device=SIM-MON-01 --fast` to refresh.
- Service crashed: restart that terminal; data persists. As a last resort, `npm run seed:reset` and re-run.
- Keep screenshots of each step as a backup.

## Things not to say

"Clinically validated", "proven AI accuracy", "predicts deterioration", "reduces mortality", "approved", "deployed in hospitals", "connected to real monitors", "uses GPT/Azure" (it is Demo Mode and templated), "the AI decides".

## Backup three-sentence version (if time is cut)

Monitoring shows quality and staleness honestly → an explainable alert arrives with its evidence → AI assistance summarises and drafts, but a named clinician must complete, record and resolve, and everything is auditable.


## Optional live Azure segment (only if verified on the day)

1. Settings → **AI assistance** (as administrator): show "Azure configured", click **Test Azure connection**, show "Connected" and the recorded time.
2. On the alert, select **Azure OpenAI**, **Summarise this alert**. Point out: the teal "Generated by Azure OpenAI · <model>" label (templates are amber and dashed), the source tags on each fact (hover one), "Not known" items, and **What the AI did not have**. Open **Checks, sources and limitations**: say "automated checks passed, which is not the same as clinically correct".
3. **Prepare draft assessment** → **Reject draft** to show the clinician's explicit rejection, then prepare another, acknowledge the alert, edit, complete the three bracketed fields and record. History shows "generated by Azure OpenAI ... Edited and recorded by the clinician".
4. Administrator → AI activity: model, outcome, checks, and the clinician decisions (Rejected, Recorded (edited)).
5. Optional resilience moment: before the demo, set an invalid `AZURE_OPENAI_API_KEY` in a copy of `.env`, restart the API, and show the clear error with **Switch to Demo Mode and run again**. Restore the real key afterwards.

If you have no Azure connection, do steps 3 and 4 in Demo Mode (the same flow, template text).
